# 白模预演合同

白模预演合同是现有制作拆解中“可选 Blender 白模预演 → Shot 交接”的一小段，不是第二份 Shot 清单、资产索引或审批表。只在项目选择 Blender 白模预演时填写。

## 输入字段

| 字段 | 必须表达的内容 |
|---|---|
| `Shot / H3` | 已存在的稳定 Shot ID；不创建预演专用 Shot。 |
| `白模资源` | 角色代理、静态姿势或已验证连续动作、场景模块、关键道具，以及路径/接触关系。名称只能来自 [本机白膜资源映射](local-whitebox-resource-map.md) 的已验证资源；不把源库或未验证动作直接带进项目。 |
| `场景图引导` | current 场景主图或 `Location + View` 的资产 ID 与实际路径、可见锚点、入口方向、相机工作侧。按 [场景图引导白模重建](image-guided-scene-blocking.md) 建立当前可拍摄空间；反打/门内外另写对应 View。 |
| `白模场景` | 对应 `Location + View`、入口、固定地标、关键道具占位和必要空间拓扑。 |
| `帧范围 / FPS / 时长` | 写实际编辑时长与预演容器时长；FPS 使用项目设置，未指定时为 24。若当前 H3 对视频参考仍要求至少 2 秒，短编辑镜头使用同机位、无新事件的 2 秒以上预演/H3 容器，再由必剪裁出实际编辑时长。 |
| `预演相机` | 相机 ID、景别、机高/角度、焦距或 FOV、摄影机工作侧、起点、唯一主运动和落点。 |
| `Camera Area / 画面层次` | 同一 Location + View 内的合法摄影区域、基础观看方向，以及前景/主体/后景；Area 内可改变距离、高度、焦段、景别、过肩和遮挡，但不破坏轴线、屏幕方向或固定锚点。 |
| `调度 / 动作节拍` | 人物与道具的起止位置、朝向、视线、持物、触发、身体准备、执行、反应和结果；人物动作按需写姿态、重心、头部、肩膀、手臂/手、腿、躯干和 `mid_state`；跨镜连接道具按需写归属者、两端、路径/余量和当前模式。 |
| `多人 / 群像站位` | 仅三人以上、围堵、队列或群像关系重要时填写：具名角色的命名锚点/画面区域/朝向，匿名 `Crowd-*` 簇的人数/区域/整体朝向/密度、入口通道，以及本 Shot 唯一允许移动或重排的人/簇。 |
| `固定锚点` | 3–5 个实际可见的入口、门窗、桌面、设备、地标或空间边界；极简场景只列真实存在的锚点。 |
| `覆盖 / 交接` | 同场有前一 Shot 时，写相对上一镜的景别/观察侧/人物或道具关系变化、切点理由，以及上一末态如何到达本 Shot 开场。 |
| `动态变化` | 相对上一 Shot 的 Camera / Body / Information 变化；通常至少两项可读变化，明确固定覆盖除外。 |
| `输出` | `.blend`、实际预演视频、选定起/中/止帧和相机合同的真实路径；若供 H3 使用，写明实际 `<Video N>`/`video_N_frames` 槽、编辑时长/预演容器时长、只控制的摄影/调度/动作域，以及不控制的最终美术/身份/道具/声音域。 |

裸写“左/右”一律是观众画面左/右。角色身体部位必须明确为“角色的左手/右侧”。门内/门外、正反打另一侧或越轴后的重建是不同的 `Location + View`，不能只写“换另一边”。

## Project output layout

在项目目录内保留预演源与结果，和 ComfyUI 原始生成及最终采用资产分开：

```text
项目/<story>/预演/<episode>/
├─ build_whitebox_previs.py
├─ <episode>_whitebox_previs.blend
├─ SHOT001_previs.mp4
├─ SHOT001_start.png
├─ SHOT001_middle.png
├─ SHOT001_end.png
└─ SHOT001_camera_contract.json
```

`camera_contract.json` 由现有制作拆解与 Blender 场景派生，不手工维护第二份镜头数据。它至少包含 Shot ID、帧范围、FPS、相机 ID、焦距/FOV、相机与目标在起止帧的位置、工作侧、预演帧路径和固定锚点。预演视频用于 H3 时，还记录实际视频路径、`<Video N>`/H3 `video_N_frames` 槽与其限定控制域。实际输出格式应服从当前 Blender 项目脚本与已验证的 LibTV 导入方式。

## Camera translation

Blender 可以精确保存坐标与曲线；接入 H3 的预演视频会强化相机、调度和动作路径参考，但 H3 仍是生成模型，不能承诺逐帧复刻。交接时保留：

- 景别、机位高度/角度、焦距或等价 FOV；
- 画面左右、轴线、工作侧和固定锚点；
- 单一主摄影行为的起点、触发、幅度、主体关系与落点；
- 人物/道具的开场关系和结束状态。

不要把多段复杂曲线、逐帧坐标或白模材质冒充为 H3 的确定性控制。一个 Shot 需要第二个独立摄影行为时，按真实剪辑理由拆到另一个 Shot。预演视频只作为同 Shot 的 `<Video N>`，不替换彩色 `<Picture 1>`，也不携带或复用其原始音频。

## Previs acceptance

预演通过至少满足：实际可播放/可解码；Shot ID 与帧范围正确；摄影机、角色代理和动作关键帧确实存在；起/中/止帧中的 Camera Area、景别/机高/焦段、前景/主体/后景、画面关系、工作侧、入口/锚点、身体动作阶段与动作结果和制作拆解一致；相邻 Shot 的必要持物、方向与空间状态能接住，并兑现已声明的 Camera / Body / Information 变化。多人场面还要验证具名角色与 `Crowd-*` 簇的区域、朝向、人数/密度和通道只发生已声明的变化。连接道具还要保持归属者、两端、路径/余量和模式，连接或解开只能在已声明的动作中发生。直接切点必须有可读覆盖变化；路径动作还要验证人物相对锚点的位置、行动阶段、朝向和道具归属可从上一末态抵达下一开场。若作为 H3 视频参考，还必须是一个不跨场、无 UI/文字/拼贴的连续镜头，参考时长符合当前 H3 能力；为最短时长加入的余量不能增加事件或改机位，并在实际请求中逐项映射到 `<Video N>` 和 `video_N_frames`。

整集的多 Shot 导出或 LibTV 导入必须以实际当前插件/渲染行为验证。若插件只可靠接收单一活动相机，则按 Shot 独立渲染和导入，不假定 Blender 多机位标记会被自动解释。
