# 视觉资产案例库

案例图用于明确板式、信息层级和最低可用质量，不是新项目的内容素材。制作身份板、场景板、道具板、项目母色板或完整导演故事板时，先查询 `../assets/examples/example-library.json`；对应条目存在 `current` 文件时，生成前查看该图，生成后用同一结构目标做真实图片 QA。

## 两层使用

1. **默认：制作代理审阅范例**。案例只供理解布局、画面面积、信息密度和可读性，不进入图片请求，因此不占参考位，也不会污染项目内容。
2. **例外：静态模型布局参考**。只有连续生成证明模型无法稳定理解板式时，才把对应案例作为有序 IMAGE 批次的最后一张参考。提示词必须逐图声明：`仅控制板式与信息层级；不得控制人物、场景、道具、综合色彩、文字或剧情`。项目 current 身份、地理、道具和 Palette 永远优先。

案例图不得登记为项目制作资产，不得复制到项目资产目录，不得进入 H3 Picture、视频、剪辑或交付。案例库更新不要求旧项目重做已经通过的资产。

## 五类标准案例

### `identity_board`

- 展示约 35%–40% 的颈根以下身体结构区，以及约 60%–65% 的头部身份区；
- 头部默认仅三个大视图：最大正面、一个 3/4、一个侧面；
- 只参考区域比例、视图数量、留白、分隔和可识别尺度；
- 不继承案例人物的脸、年龄、身体、发型、服装、肤色、表情或文字。

### `scene_board`

- 展示一张 16:9、2×3 的同一地点多视角场景板；
- 主视角、反向、左右斜角、入口/连接与俯视拓扑职责清楚；
- 只参考六区职责、主次面积和地理可读性；
- 不继承案例建筑、陈设、时代、材质、光源、颜色或标签。

### `prop_board`

- 以一个主要英雄视图配合必要角度、结构/机制细节和尺度信息；
- 视图数量由真实识别需求决定，不为了填满画布增加重复角度；
- 只参考主次关系、细节尺度和留白；
- 不继承案例道具的形制、数量、材质、功能、状态或文字。

### `project_palette`

- 展示三条清楚分组的横向综合色带：基础/中性锚点、环境/光线色族、角色/道具/叙事强调色；
- 只参考三层分组、色块可读性和简洁程度；不得继承案例具体颜色；
- 它是影视综合色彩关系参考，不是印刷或像素级 RGB 校准图。允许色块内部存在不改变其主要色相、明度层级和职责识别的轻微生成变化；明显渐变导致色块变成材质/光影样片、出现人物场景文字或错误色族时才返修。

### `director_storyboard`

- 展示紧凑页眉、大幅有序电影镜头、格外 Panel/Shot ID 与相对时间、底部真实参考/简短 Shot 表；
- 案例只固定信息层级和可读性，不固定格数、行列、时长或镜头内容；
- 不继承案例剧情、角色、场景、道具、构图、镜头顺序、文字或综合色彩。

## 入库条件

正式案例必须来自主人明确认可的成品或专门制作并通过真实图片 QA 的中性示例。入库时更新 `example-library.json` 的相对路径、版本、来源说明和 `current` 状态。不得用空白占位图、网络截图、带权利疑问的图片或尚未通过的候选冒充标准案例。

替换案例时保留旧文件版本，不删除；清单只把一个版本标为 `current`。这只是 Skill 自身的案例清单，不是项目候选池、审批账本或生成 Gate。
