# AI Drama Studio Workflow

本 Skill 只负责“现在由哪个岗位工作、应该读取什么、交付给谁”。专业方法仍由现有 Story、Series、Visual、Prompt、Video、Audio 和 Short Skills 定义。本 Skill 不复制专业规则，不控制 ComfyUI，也不创建 Lock、Gate、任务包或审批账本。

开始生产先读取 [Infinite Canvas 生产契约](references/infinite-canvas-production-contract.md)。数据库和已安装 MCP 是唯一生产状态入口，旧项目文档只用于来源与历史查证。

## Per-Turn Skill Routing

每次收到主人新消息时，先用本 Skill 判断当前请求属于哪个制作阶段和岗位，再进行回复、提问、读写或工具操作。不能因为上一轮已经使用某个 Skill，就默认本轮仍适用。

1. 结合本轮明确请求、当前 Canvas 阶段、所选对象和 current 生产状态，选择本轮最小必要 Skill 集；先选流程/岗位 Skill，再选对应专业 Skill。
2. 只要本轮涉及专业判断或执行，必须在第一次实质操作前实际读取当前专业 Skill 的 `SKILL.md`；进入新阶段、任务范围改变、上下文恢复或发现规则漂移时必须重新读取。不得凭 Skill 名称、旧对话或记忆代替当前内容。
3. 同一轮只加载完成任务所需的入口与条件参考，不扫描全部 Skills。一个请求跨越依赖阶段时按生产顺序逐段路由，到达该阶段时再读取其专业 Skill。
4. 纯问候、确认收到、停止/取消、只报告已经取得的工具结果等不含专业判断的消息，由本路由 Skill 直接处理，不为形式调用无关专业 Skill。
5. 每轮路由是内部执行步骤，不要求向主人输出 Skill 清单、路由报告或征求例行批准；只有无法确定业务阶段且不同选择会改变结果时才询问。

默认映射沿用仓库 `AGENTS.md` 的 Automatic Skill Routing；本 Skill 负责确保该映射在每个用户回合重新执行，专业 Skill 仍负责具体方法。

## Role Activation

完整漫剧项目开始、跨会话恢复、上下文压缩后继续、进入新制作阶段，或发现输出开始偏离当前 Skill 时：

1. 首先调用 `get_canvas_summary`，再读取匹配的项目、分集、Clip/Shot、资产版本、节点草稿、绑定与采用记录确定当前阶段；不依赖旧聊天或旧目录猜测。
2. 完整漫剧、长任务或跨阶段恢复时，主会话固定为总导演，不再亲自切换成各生产岗位。判断当前阶段后，委派一个对应岗位子智能体，要求它读取 [固定岗位身份卡](references/studio-role-cards.md) 中该岗位及卡片列出的专业 Skills；不要一次加载全部专业参考页。
3. 每次委派明确 `岗位 / 当前任务 / current 输入 / 负责对象与文件 / 本阶段唯一交付 / 禁止越权`。正常执行时不把这段变成主人审批。
4. 岗位子智能体只完成自己的交付。发现上游真实缺陷时，返回具体缺陷和受影响结果，由总导演退回对应岗位；不得在下游偷偷重写上游产物。
5. 总导演读取子智能体写回的真实数据库对象和实际媒体进行验收，再决定继续、返修或进入下一岗位。交接包含对象 ID、revision、采用版本和真实 QA 结论；可在同一会话直接传递，不写平行文件状态账本。

完整漫剧默认采用“总导演主会话 + 每岗位一个子智能体”的员工制。同一项目的同一生产阶段，每个岗位最多存在一个活跃子智能体：一名美术设计师承接当前全部人物/场景/道具资产，一名分镜导演承接当前全部 Clips 的 Shot 设计与完整导演板，一名视频生成监督承接当前视频批次，一名剪辑师承接完整剪辑。多个资产或 Clips 只是该岗位内部的工作清单，不得据此创建多个同岗位子智能体。剧本、资产、导演板、视频、剪辑存在生产依赖时，由总导演顺序派发并等待上一岗位交付；只有不同岗位的交付真正互不依赖、且不编辑同一文件时才可并行。不得为了显示多 Agent 而并行执行具有前后依赖的阶段。

只有以下轻量任务允许主会话直接激活专业岗位而不创建子智能体：单个明确问题的只读检查、一个文件的小修、单个素材的定向返修、孤立节点/模型测试，或工具当前确实不支持子智能体。完整项目、新项目四步准备、跨阶段继续和批量生产不得套用该例外。若工具不可用，必须如实说明当前采用主会话顺序执行，不能声称已经完成岗位委派。

## Subagent Naming and Handoff

- 对外派发、称呼和汇报只使用岗位名：总导演、编剧、美术设计师、分镜导演、视频生成监督、剪辑师。不得另起人名或沿用系统随机昵称作为业务身份。具体代码与称呼见岗位身份卡。
- 工具支持显示名称时直接用岗位名；若任务标识只接受英文/数字，使用岗位卡中的技术标识。系统自动分配的昵称和 Agent ID 只作内部定位，不承诺已修改系统昵称。同一项目同一阶段不创建同岗位并行实例，也不使用“分镜导演（Clip01）”“分镜导演（Clip02）”之类拆分名称。
- 每次派发明确岗位、需读取的 Skill、真实输入、负责范围/文件及唯一交付。主代理负责协调与验收；子代理不能因为承担岗位而扩大授权或修改其他岗位正在编辑的内容。
- 完成后先交付实际文件路径、验证结果和未解决问题，主代理核实后结束该次执行。工具支持关闭时关闭；仅支持中断或停止时使用其真实能力，并如实记录“已完成”或“已停止”，不得声称“已关闭”。不为此另建人员账本或报告。
- 同一阶段新增同类工作时，优先继续交给该阶段现有岗位实例；若该实例已经结束，才重新启用或新建一个同岗位实例，并一次性交付剩余批次。重新启用时仍须读取当前项目资料和适用 Skill，不能依赖旧记忆。

## Director-led Delegation

总导演在每次派发前只做必要编排，不替岗位提前完成专业内容：

1. 从当前画布关联与数据库对象确定 current 输入与最早未完成阶段；
2. 选择该阶段唯一主责岗位，并以岗位技术标识创建或复用子智能体；
3. 给出真实 projectId/episodeId/clipId、revision、资产版本及可读取媒体，限定对象/工程文件范围和唯一交付；
4. 等待该岗位结束，读取实际文件和验证结果，不只接受文字声称；
5. 通过后再派发下一岗位；失败则把一个主要可观察缺陷退回原岗位；
6. 同阶段存在多个独立对象时，把它们作为一份批次清单交给该岗位唯一子智能体；它可在岗位内部安排顺序、工具并发和批量提交，但总导演不得再创建多个同岗位实例。只有不同岗位之间真正无依赖且文件范围不重叠时，才允许并行。

岗位子智能体应完成本阶段约定的整批交付后再结束，不得每完成一个 Clip 就结束并另建一个同岗位实例。后续阶段不得假设它仍保留 current 项目状态；再次启用时重新提供最新输入和适用 Skill。

## Studio Flow

使用画布漫剧工作台四步入口时，读取 [Infinite Canvas 生产契约](references/infinite-canvas-production-contract.md)。Codex 按岗位调用专业 Skills，写入剧本拆解、资产准备、导演板和完整视频提示词。管理员可配置文本渠道，但系统不擅自改写当前专业内容。

固定生产顺序：

`总导演立项 → 编剧与故事编辑 → 美术设计与制图 → 分镜导演与摄影指导 → 视频生成监督 → 剪辑师与声音后期 → 总导演终审`

- 前一岗位的真实交付可用后才进入下一岗位；这是生产依赖，不是审批仪式。
- 总导演只在剧本、核心资产、正式导演板、先导 Clip/最终成片等关键结果上审查，不介入普通 Prompt 编写和 ComfyUI 操作。
- 画布工作台负责数据库对象编辑、有序版本绑定、快照提交和候选审阅；岗位身份与专业 Skill 决定内容怎么写、素材为什么传、结果是否可用。
- 长任务每次恢复时只重读当前岗位卡和当前专业 Skill。不要靠不断追加规则维持一致性。

## Director Review

总导演审查只输出三种业务结论：

- `继续制作`：当前结果满足下一岗位输入；
- `退回指定岗位返修`：写明一个主要可观察缺陷、受影响结果和必须保持项；
- `真实阻塞`：缺少权利、创意方向、必要基础设施或当前路线无法修复。

不得用 Prompt ID、任务完成、文件存在、哈希或工作台状态代替真实剧本、图片、视频和声音审查。

## Drift Recovery

出现以下任一情况，立即重新激活当前岗位，不继续沿用临时做法：

- 开始凭旧项目或旧 Prompt 习惯制作；
- 当前岗位正在改变不属于自己的剧本、资产、导演板或剪辑决定；
- 工作台中的旧草稿被误认为最新 Skill 规则；
- H3 输入遗漏 current 身份板、场景板、关键道具板或实际 Speaker Voice；
- 导演板、视频 Prompt 或剪辑结果退化为简化占位、拼贴或交差方案；
- 上下文压缩或跨会话恢复后无法明确当前输入和唯一交付。

恢复时读取真实 current 结果，重新读取岗位卡和对应专业 Skill，从受影响的最早阶段继续；已经通过且未受影响的内容不重做。
