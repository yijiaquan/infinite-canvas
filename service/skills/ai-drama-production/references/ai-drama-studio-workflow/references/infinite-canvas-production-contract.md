# Infinite Canvas Production Contract

这是当前漫剧生产的数据与执行契约。专业 Skill 决定内容质量；无限画布数据库是项目、分集、Clip、资产版本、绑定、任务和采用记录的唯一生产状态源。源码、原小说、版权凭据、Blender/必剪工程和导出文件仍可保存在磁盘，但不以磁盘副本回写覆盖数据库。

## Discover and Resume

1. 首先调用当前会话真实可用的 `get_canvas_summary`，确认连接、账户及当前 canvasId；再通过已安装 MCP 的项目、分集与 Clip 读取能力确认 projectId、episodeId、clipId 与 revision。
2. 一部剧一个项目，一集一个正式画布。恢复时读取该集剧本、Clip/Shot、实际节点草稿、资产版本与采用项、有序输入绑定、任务快照及候选。不要从旧聊天、文件时间或节点显示图片推测采用结果。
3. 以下名称描述能力，不保证当前插件的工具拼写：读取/更新项目、分集、Clips、资产，创建/排序/归档/恢复 Clip，创建资产及版本，准备 Clip 节点，更新生成节点，读取/更新绑定，预览/入队/取消/核查运行，读取/采用输出，导出分集。调用前读取实际工具 schema；不可把不存在的能力伪装成已执行。
4. MCP 缺少能力时先报告具体缺口并使用本项目已实现的正常工作台 UI；不能转回旧工作台、直接写数据库、猜 API 或手工请求 ComfyUI `/prompt`。连接或身份不明时只读暂停写入。

## Authoritative Objects

- 项目保存来源正文、改编蓝图、系列设定和全局风格；分集保存制作剧本；Clip 保存剧情、场次、稳定 Shot ID、时长、动作、精确对白、说话者、摄影、声音及起止状态。仅更新真实存在的字段，专业补充可留在所属对象的描述/正文，不新建平行控制表。
- 原著/剧本初稿可以是文档；投入生产前通过正常项目/分集写入能力登记并读回。进入下游后数据库中的版本为准，不能要求每轮另外生成状态 Markdown 或资产索引。
- 人物、造型、人物表情板、场景、View、道具、声音与其他参考由资产对象及不可变版本表达。引用使用返回的 assetId、versionId、storageId；人类语义名称和 Character/Look/Location/Prop 标识不代替数据库 ID。`kind: "expression"` 是完整人物表情板，`parentId` 必须指向对应 Character 或具体 Character Look；可直接进入视频的单状态干净图片仍使用 `kind: "reference"`，且 `parentId` 必须指向来源表情板。其他派生对象继续使用已支持的 parentId 或描述，不为表情板增加数据库列。
- 已通过真实 QA 的资产版本由 adoptedVersionId 指定；新候选不会自动替换采用版本。Clip 已绑定旧版本时保持不变，更新必须显式预览和保存。归档不删除历史媒体。
- 每个 Clip 的组、导演板节点和视频节点与业务记录关联；节点 prompt 是生成草稿的唯一副本。普通几何连线不自动修改数据库输入绑定；使用正常绑定能力维护实际输入并由画布显示对应节点和连线。

## Inputs and Prompts

输入绑定是有序的 assetId + versionId + role + order，声音还带实际 speaker。人物表情使用 `role: "expression"`：导演板节点只接受完整 `expression` 资产；视频节点只接受父级为 `expression` 的单状态图片 `reference`。图像/声音必须先成为服务器可解析的持久媒体；浏览器 blob、临时路径、未登记的 guest WebDAV key 和人工短 ID 不能当作 storageId。

### Infinite Canvas 源提示词标准

- Codex 只编辑画布节点的语义正文，并通过工作台保存结构化媒体绑定；不使用旧文本提及解析器，也不直接操作 ComfyUI 提示词。
- 源节点引用媒体时只使用 UI 插入的缩略图令牌 `图片N`、`视频N`、`音频N`。令牌编号必须与当前节点预览中的有序绑定一致，正文中的资产名称不创建绑定。
- 源节点禁止出现提供方标签 `<Picture N>`、`<Video N>`、`<Audio N>`。这些标签仅允许存在于预览/提交产生的只读编译结果和已冻结运行快照中，由适配器根据本次真实媒体顺序生成。
- 修改正文或绑定后必须重新预览：源节点仍显示缩略图令牌，编译结果显示对应提供方标签，二者顺序和职责一一对应。不得把编译结果复制回源节点。
- 专业 Skill 中的提供方标签示例只用于定义编译结果及验收规则，不是画布源提示词模板。系统不擅自改写 Shot、对白、时间线或专业提示词。

视频执行要求本 Clip 存在通过 QA 的完整导演故事板和对应规划连接，但 Ref2VA 执行适配层不上传故事板，也不把它加入 Picture 编号。实际出镜身份、关键近景所需单状态表情参考、当前场景、关键道具、必要预演和实际 Speaker Voice 按各专业 Skill 选取。完整宫格表情板只能绑定导演板节点，禁止直接进入视频。H3 普通图片顺序固定为实际出镜身份板、所需单状态表情参考、当前场景板、关键道具及其他必要参考；八图不足时优先保留身份板和场景板，只有表情承担关键剧情信息时才让它优先于次要道具或一般参考。绑定/角色/顺序改变后重新预览核对提示词，不修改已经提交的快照。

### H3 Ref2VA No-First-Frame Mapping

当前 Ref2VA 不自动把完整导演板或任何普通资产接入 `picture_1_keyframe`。完整导演板保留为 Clip 的审核、Shot 规划和提示词编译依据，但不是本次 H3 的媒体输入；实际人物、单状态表情、场景、道具、视频和 Voice 才按当前结构化绑定接入可选参考槽。场景图即使是第一张实际参考，也只能承担地理、固定锚点、入口、主光和材质等窄职责，不能成为 0 秒端点。只有主人明确选择 I2VA 首帧模式或 FL2VA 首尾帧模式时，才连接经过独立 QA 的端点图像。该规则优先于本文其他历史的“导演板首图”说明。

## Execute and Adopt

- 使用管理员已配置的图片/文本/视频/音频渠道。图片可直接走配置的图片 API；ComfyUI 仅作为所选工作流的执行后端，不是漫剧管理入口。H3 使用管理员已批准的当前工作流和暴露参数；不在生产时改隐藏图节点、替换模型或自行降步数。
- 提交前读取当前 revision，预览最终提示词、参数与实际输入，核对对应 Clip/节点，再入队。并发冲突时重新读取并保留当前草稿，不静默覆盖别人的版本。
- 入队冻结快照，后续草稿修改不取消任务。未提交到执行后端的排队取消不收费/应退回预扣；已经提交的取消不退费。`unknown` 必须核查，不以重发验证状态，不自动重试造成重复扣费。
- 生成成功与媒体保存成功都不等于采用。看图、正常速度看片/试听后明确采用真实输出；节点显示候选与采用记录不同。Clip 修改后按系统待复核状态重新审阅，不能直接把旧采用当成新内容通过。
- 交接传递项目/分集/Clip/资产版本/运行与采用 ID、revision、可读取媒体和实际 QA 结论。使用数据库现有字段与会话交接，不发明审批表、锁、文件台账或新的状态数据库。
- 导出采用素材包供必剪使用；保留现有剪辑顺序、裁切和音轨。导出清单、真实文件与正常速度 QA 一起验收，不能只凭 ZIP/HTTP 成功宣布成片完成。发布仍需要明确授权。

## Legacy and Technical Lab

旧工作台状态目录、本地资产台账、流程状态文件、旧 API、项目脚本和模板只供历史查证或明确的一次性导入；不创建、扫描同步或回写它们，不用它们恢复新画布生产。旧技术实验的 ComfyUI 工作流、请求、哈希和 `ComfyUI输出` 证据保留不动。只有明确技术实验任务才加载 Lab 参考页；实验结果不自动成为正式资产或采用项。
